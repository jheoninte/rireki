# 클라우드·수익화 기능 연결

서버 기능은 구현 후 설정을 기다리는 상태입니다. 기존 운영 Supabase에 마이그레이션을 실행하거나 Stripe/OpenAI 계정을 연결하지 않았습니다. 통합 UI와 호환 주소는 운영 사이트에 배포했으며, 환경변수로 서버 기능을 분리했으므로 기존 인증과 무료 다운로드는 계속 사용할 수 있습니다.

## 제공 범위

- 이메일·비밀번호 기본 로그인. Google과 설정한 GitHub/LinkedIn/Facebook/Kakao 제공자 표시.
- 계정별·언어별 클라우드 이력서 1개. 명시적으로 처음 저장/읽기한 뒤 1.2초 지연 자동 저장.
- 수정 버전 검증으로 다른 기기의 수정을 덮어쓰지 않음. 충돌/통신 실패 시 동기화 중지 → 재확인 후 사용자가 선택.
- 게스트, 로그인한 계정, 읽기 전 백업의 브라우저 키를 분리. 기존 게스트 초안은 로그인 후 직접 가져오기.
- 무료 기본 서식 2개, 직군별 유료 서식 3개, 텍스트 중심 서식 1개. 유료 패스는 로고 제거 포함 US$2.99 단건 구매.
- AI 크레딧 20개 US$2.99 단건 구매. 확인된 이메일 계정당 2회 무료, 1회 1크레딧, 일일 최대 30회.
- 모바일 입력/미리보기 전환, 클라우드 활성 환경에서 50% 진행 시 로그인 권유, 입력별 팁·직군별 예시, 완료 후 채용 탐색·체크리스트.

## 1. 데이터베이스

먼저 별도 테스트 프로젝트에 `supabase/migrations/202611200001_workspace.sql`을 적용합니다. CLI를 쓰면 프로젝트 연결 후 `supabase db push`, 대시보드에서는 SQL Editor로 파일 전체를 실행합니다. 테이블/함수를 만드는 최초 마이그레이션이므로 같은 SQL을 반복 실행하지 않습니다.

`resumes`에는 본인 읽기 RLS만 있으며, 쓰기·삭제는 `auth.uid()`를 검증하는 함수에서 처리합니다. 결제·잔액·예산 테이블은 클라이언트 접근을 금지합니다. AI 예약·완료·결제 지급·환불 함수는 service_role만 실행할 수 있습니다. service_role은 프런트에 넣지 않습니다.

Supabase Cron 확장을 활성화한 뒤, 신뢰할 수 있는 서버 스케줄러에서 **10분마다** `select public.reconcile_coaching();`를 실행합니다. Edge 프로세스가 강제 종료되어 10분 넘게 남은 AI 예약을 환불합니다. 공급자가 청구했을 수 있으므로 비용 예산은 반환하지 않습니다. 예약이 2분 넘게 남으면 새 요청은 가능하지만, 이 정리 작업 전까지 해당 크레딧은 예약된 상태입니다.

동일 계정 두 브라우저에서 저장 → 한쪽 수정 → 다른 쪽 저장 시 충돌 표시를 확인합니다. 로그아웃 후 다른 계정에서 앞 계정의 이력서·클라우드 행이 보이지 않는지도 확인합니다. 최초 저장 및 삭제 후 재생성에도 전역 증가 버전을 써서 오래된 기기의 저장이 통과하지 않게 했습니다.

검증 후 프런트 `.env.local`에 `VITE_CLOUD_ENABLED=true`를 지정합니다. 플래그를 켜도 로그인만으로 내용을 업로드하지 않습니다.

## 2. 소셜 제공자

Supabase Auth → Providers에서 사용할 제공자의 OAuth 클라이언트를 연결하고 콜백/허용 도메인을 설정합니다. `VITE_SOCIAL_PROVIDERS=google,github,linkedin_oidc`처럼 활성화한 제공자만 명시합니다. Facebook·Kakao도 지원하지만 사업자/앱 심사 여부는 제공자 정책을 따릅니다. 메일·비밀번호가 먼저 표시되고 소셜 버튼이 뒤따릅니다. 기존 Google 연결만 된 환경에서는 기본값 `google`을 유지합니다.

## 3. Stripe 단건 결제

1. 테스트 모드에서 두 상품을 만들고 각각 **USD 2.99, one-time** 가격을 생성합니다. `pro`는 템플릿 패스, `credits`는 20회권입니다. 정기 구독은 생성하지 않습니다.
2. 서버 전용 비밀값은 `supabase/.env.example`을 참고해 설정합니다. 가격 ID는 프런트 요청에서 받지 않습니다. 서버가 실제 가격의 통화·금액·단건 유형을 검증합니다.
3. `supabase functions deploy checkout`, `supabase functions deploy coach`, `supabase functions deploy stripe-webhook`을 실행합니다. 저장소의 `supabase/config.toml`을 적용합니다. checkout/coach는 핸들러에서 `auth.getUser()`로 JWT를 검증하고, webhook은 원문 HMAC으로 인증합니다.
4. Stripe webhook 목적지: `https://<project-ref>.supabase.co/functions/v1/stripe-webhook`. 이벤트는 `checkout.session.completed`, `checkout.session.async_payment_succeeded`, `charge.refunded`, `charge.dispute.created`를 선택합니다. 서명 비밀값을 설정합니다.
5. 성공/취소 URL은 서버의 `APP_ORIGIN`에서 만듭니다. 성공 URL 방문 자체는 권한을 주지 않습니다. 검증된 paid 세션과 가격·금액·사용자 매칭에 성공한 webhook만 권한을 지급합니다. 이벤트·세션·payment intent 각각 중복 지급을 차단합니다.
6. 테스트 결제 후 잔액 갱신, 같은 webhook 재전송, 다른 이벤트 ID로 같은 세션 재전송, 환불·분쟁 이벤트를 점검합니다. 반환된 서명에 유효한 `v1`이 여러 개 있어도 처리합니다.

환불/분쟁은 크레딧 회수와 AI 일시 정지를 수행합니다. 패스는 다른 유효한 구매가 없으면 회수합니다. 부분 환불도 검토 대상으로 처리하며, 운영자가 정산 후 `accounts.suspended`를 해제합니다. 이미 사용한 AI 비용이나 Stripe 분쟁 수수료까지 회수할 수는 없습니다. 이 이벤트가 결제 완료보다 먼저 도착하면 500으로 응답해 Stripe의 재전송을 받습니다.

세금 자동 계산·쿠폰·구독은 이 버전에 없습니다. 추가하면 webhook 금액 검증과 요금 안내도 함께 변경해야 합니다. 실제 판매 전 사업자·관할에 맞는 세금, 판매자 고지 및 환불 약관을 등록합니다. 판매자 계정에 Stripe가 지원되는지도 확인합니다.

## 4. AI 비용과 손익

무손실 수익을 보장할 수는 없습니다. 무료 체험, 서버 비용, 환불·결제 수수료가 있으므로 **단가 여유와 총지출 한도**를 함께 적용합니다. 서버 비밀값이 없으면 API 요청을 실행하지 않습니다.

| 항목 | 제한 |
|---|---|
| 모델 | `gpt-4.1-mini-2025-04-14` 고정, 브라우저가 모델 변경 불가 |
| 입력 | 선택한 텍스트 최대 2,000 UTF-16 문자 + 고정 시스템 지시문 |
| 출력 | 최대 700 토큰, 정상 완료 응답만 사용 |
| 공급자 호출 | 예약 성공당 한 번, 자동 재시도 없음, 45초 타임아웃 |
| 유저 무료 체험 | 확인된 이메일 계정당 2회 |
| 전체 무료 체험 | 예시 설정은 하루 5회, 실패한 시도도 일일 횟수에 포함 |
| 유저 요청 수 | UTC 기준 하루 30회, 진행 중 요청 제한 |
| 전체 예산 | 예시 설정은 하루 $0.10, 시도당 $0.01 선예약, 실패해도 예산 차감 유지 |

입력 토큰 비용 $0.40/백만, 출력 $1.60/백만이라는 **가격 가정**에서 한 요청의 실제 모델 비용은 1센트 예약액보다 작도록 길이를 제한했습니다. 운영 전 OpenAI의 현재 모델 가격을 확인하고 가격 변경 시 `reserve_coaching`의 예약액·판매가를 함께 조정하세요. 예약액은 실제 청구액을 실시간 조회하는 값이 아닙니다. 공급자 요금 인상·별도 API 키 사용까지 막는 청구 한도는 아닙니다.

20회권을 모두 사용해도 비용 예약액은 $0.20입니다. 예를 들어 결제 수수료를 3.6% + $0.30으로 **가정**하면 $2.99 − $0.408 − $0.20 = 약 $2.38가 남으며, 여기서 세금·환전·서버·지원·환불·무료 체험 비용을 충당해야 합니다. 실제 수수료는 사업자 국가·카드·정산 통화에 따라 다릅니다. 무료 체험 5회/일의 예약 원가는 최대 $0.05/일, 약 $1.50/30일입니다. 매출이 없어도 이 비용은 생길 수 있습니다.

사전 적자가 허용되지 않으면 `AI_FREE_DAILY_LIMIT=0`으로 시작해 템플릿 판매 이익에서 무료 체험 예산을 배정합니다. 최소한의 체험을 먼저 제공하려면 예시의 $0.10/일을 마케팅 예산으로 미리 확보합니다. `AI_DAILY_BUDGET_MICRODOLLARS`는 명시적으로 설정하며, 예산 미설정 또는 한도 도달 시 차단됩니다. 무료 한도는 호출 주체가 정할 수 없고 service_role 함수만 전달합니다.

Supabase 가입 CAPTCHA·이메일 확인·인증 요청 제한을 함께 켜 다중 계정 남용을 줄입니다. Supabase/Cloudflare 요금제의 지출 통제와 OpenAI 사용량 경보도 별도 설정합니다. 운영 중 `ai_budget`, 실패/미완료 요청, Stripe 환불과 webhook 실패를 모니터링합니다.

AI가 서버에서 반환한 결과는 재전송 복구를 위해 DB에 저장됩니다. 개인정보 보유 정책을 정해 정리 작업을 적용하세요. 계정 삭제 시 이력서·잔액·AI 요청·결제 연결 행은 cascade로 삭제되지만, 법정 결제 보관 기록은 Stripe 및 별도 회계 정책을 따릅니다.

## 5. 프런트 활성화·배포

모든 서버 설정과 Stripe 테스트 검증 후 `VITE_COMMERCE_ENABLED=true`로 빌드합니다. 미설정 환경은 유료 구매·AI를 준비 중으로 표시합니다. 기능 플래그는 빌드 시 반영되므로 다시 빌드하고 배포해야 합니다. 운영 연결 전 테스트 키로 검증하고 라이브 전환 시 Stripe 가격 ID와 webhook 비밀값도 라이브로 바꿉니다.

브라우저 렌더링인 템플릿·워터마크는 강한 DRM이 아닙니다. 일반 UI는 서버에서 확인한 구매 권한으로 다운로드를 제한하지만, 개발자 도구를 사용하는 사용자가 프런트 코드를 변조하는 것까지 막지 못합니다. 강제 보호가 필요해지면 PDF 렌더링을 서버로 옮겨야 합니다. 반면 AI 호출·크레딧·결제 지급은 현재도 서버에서 검증합니다. Word는 텍스트 중심 문서이며 각 PDF 디자인을 그대로 재현하지 않습니다. 이미지 PDF의 ATS 통과율은 보장하지 않습니다.

제휴 계약을 맺은 뒤 `VITE_CAREER_PARTNER_URL`에 실제 HTTPS 링크를 지정하면 광고/수수료 고지와 함께 노출됩니다. 기본 Wantedly 링크는 일반 외부 링크이며 제휴 수익이 연결되어 있지 않습니다. 이력서·연락처를 URL에 포함하거나 자동 전달하지 않습니다.

```sh
pnpm test
pnpm build
pnpm dlx deno check supabase/functions/coach/index.ts supabase/functions/checkout/index.ts supabase/functions/stripe-webhook/index.ts
```

PostgreSQL 테스트는 PGlite에서 실제 마이그레이션을 실행해 RLS·권한·충돌·중복 지급·예산·크레딧 처리를 검증합니다. 실제 공급자 결제·메일·기기 간 통신 검증을 대체하지는 않습니다.
